--------------------------------------------------
CORE DEVELOPMENT PHILOSOPHY
--------------------------------------------------

Do not simply implement a requested feature and assume it works.

For EVERY important system:

1. Design it.
2. Implement it.
3. Test it.
4. Inspect the result.
5. Verify the calculations.
6. Test edge cases.
7. Test interactions with other systems.
8. Fix bugs.
9. Retest.
10. Refactor poor architecture when needed.

Constantly ask yourself:

"Is this actually working correctly?"

"Does this interact correctly with the rest of the game?"

"Can this break at extreme values?"

"Does the UI correctly represent what the underlying system is doing?"

"Does this feel like an actual action RPG rather than an unfinished technical demo?"

"Would a player immediately understand what is happening?"

Do not mark a feature complete merely because there is code for it.

A feature is complete only when it functions in actual gameplay.

PHYSICS AND IMPACT SYSTEM
--------------------------------------------------

Physics should be one of Beyond Heroes' distinguishing mechanics.

Implement real physical interaction where practical.

Examples:

- Knockback
- Enemy-to-wall impact
- Enemy-to-object impact
- Enemy-to-enemy collision
- Destructible props
- Breakable objects
- Heavy hits moving enemies
- Launching
- Stagger
- Weight differences
- Momentum
- Impact VFX
- Impact sound effects

A powerful attack should FEEL physically stronger than a weak one.

Create an IMPACT DAMAGE system.

Example concept:

Impact Damage =
Knockback Velocity
× Collision Severity
× Attacker Impact Modifier
× Target Weight Modifier
× Surface Modifier

An enemy violently thrown into a stone wall should potentially take additional damage.

A heavy enemy should respond differently from a small enemy.

Prevent infinite physics feedback loops or ridiculous chain reactions.

Cap and normalize extreme results where necessary.
