# bh-013 model builder brief (Builders A, B1, B2, C, D)

You build enemy models for the Godot 4.7 game Beyond Heroes (`A:\Python\beyond-heroes`). Everything is generated by
Python scripts run in Blender 5.2 — no third-party meshes, deterministic, no manual edits. The game's gameplay code
(stats, attacks, AI, spawning) is written by the Orchestrator; you deliver models that satisfy the contract below.

## Tools
- Blender: `"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe"` (run with `-b --factory-startup`).
- Godot 4.7.2: `"C:\Users\Lemon PC\Desktop\Godot.exe"` — ONLY on a scratch copy (see Validation). Never on `game/`.
- System Python 3 with numpy + PIL (for contact sheets / compose scripts).
- Shell: Git Bash (POSIX) or PowerShell. Windows paths.

## Humanoid contract
- Module `tools/blender/characters/enemy_<id>.py` exposing what the others expose (`SCALE`, `PROPS`, `PALETTE`,
  `PALETTE_COLORS`, `CLIPS`, `build(body)`, optional `finish_mesh`). Build one character:
  `cd tools/blender/characters && "<blender>" -b --factory-startup --python build.py -- <id>` → writes
  `game/assets/characters/<id>.glb`. Copy an existing enemy's `<id>.glb.import` next to it (same settings, e.g.
  `nodes/use_name_suffixes=false`), changing only paths/uids so they are unique (delete the `uid=` line if unsure;
  Godot will assign one). The model bakes the shared enemy base clips + your `CLIPS` (exact list per model below).
- Weapons are rigid on `weapon.R` / `weapon.L` (see `K.add_weapon`), shields face -Y.
- Budget: regular monsters <= 20k triangles, bosses <= 35k. Author at the natural height given; the game scales.
- Materials: contract names `BH_*` with a per-character palette (`PALETTE_COLORS`) exactly as the existing enemies do.
  `BH_Emissive` for glows (eyes, runes, lava seams), `BH_WeakPoint` for a glowing core if asked.

## Creature contract (quadruped / 8-leg / floating)
- Script `tools/blender/creatures/build_<id>.py`, runnable like the existing ones, writing `game/assets/characters/<id>.glb`.
- Do NOT edit existing scripts (`build_wolf.py`, `creature_kit_c.py`, …). Import from them, or copy code into your own
  module if a function needs changes.
- Clip names: the generic set (`idle, idle_look, walk, run, run_combat, hit_light, hit_heavy, stagger_small, knockback,
  death, death_back, alert`) plus your attack clips, which MUST be prefixed with a unique stem given below (e.g.
  `crab_snap`). Clips in place, 30 fps.
- `game/assets/characters/creature_meta.json`: merge ONLY your own prefixed clip keys (length, loop, hits = seconds
  where the blow lands). Re-read the file immediately before writing, keep every other key untouched, write, re-read
  and verify. Other builders merge into the same file concurrently.
- Floating models follow the wisp convention exactly: static node hierarchy, no armature, origin = creature centre,
  child nodes named `core`, `ring_1`, `ring_2`, `ring_3` (each ring tilted by its own transform and spun by the game
  about its local up axis), and `ribbons`. The game hovers it ~1.2 m above ground and animates everything.

## Validation and evidence (per model)
- `python tools/blender/characters/godot_check.py --scratch <your scratch dir> --godot "C:\Users\Lemon PC\Desktop\Godot.exe"`
  or an equivalent scratch-project import of your GLBs: every listed clip must import with the right loop mode.
  (godot_check.py appends to a bh-002 validation file; if you run it, pass a scratch/output location or copy the
  script's logic into your own checker under your evidence dir — do not modify shared evidence.)
- Workbench previews: `preview_enemy.py` (`--iso` for the gameplay camera, `--clips` for poses). Look at them. The
  gameplay camera is high (about 50–55 degrees pitch) at 16–26 m: silhouettes and glow must read at that distance.
- Evidence dir `work/lemondev/bh-013/evidence/models_<group>/`: `<id>.md` (module, GLB, triangles, materials, height,
  clips, palette, what makes it distinct, build log excerpt, known limitations), `<id>_rest_iso.png`, `<id>_clips.png`.
- Up to 3 revision passes per model on your own previews. Prioritise: correct rig/clips, readable unique silhouette,
  clean deformation, then detail.

## Rules
- Write ONLY: your modules, your GLBs + `.import` files, your keys in `creature_meta.json`, your evidence dir, and
  scratch files under your own scratch dir (e.g. `work/lemondev/bh-013/scratch/<group>/`, or the session temp dir).
- Never run `build.py -- all`, `-- meta`, or anything that rewrites other characters, `anim_meta.json` or weapons.
- Never run Godot on `game/` (no `--import`, no editor). Never kill Godot/Blender by image name — only your own PIDs.
- No Filipino words, names or folklore anywhere (the user forbids it).
- Final message: a concise report — per model: id, files, triangles, height, clips (with prefixed creature clip names
  and hit times), materials/palette notes, and known limitations. Plus anything the Orchestrator must know to wire
  the model (scales, sockets, which clip is which attack).
